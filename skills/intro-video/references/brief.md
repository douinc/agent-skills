# 브리프 계약

코드를 한 줄도 쓰기 전에 아래 칸을 채운다. 모호한 한 줄 요청은 기본값 영상(가운데 제목, 그라데이션, 전부 페이드인)을 만든다. 영상의 품질은 프롬프트가 아니라 이 칸들과 검수 게이트에서 나온다.

## 묻는 방법

- 요청에 이미 답이 있는 칸은 묻지 않는다. 추론만으로는 답이 아니다. 추론한 값은 요약에 "추론"이라고 표시한다.
- 남은 칸은 한 번에 묻는다(질문 UI가 있으면 칸마다 한 질문, 추천값을 첫 선택지로 두고 이유를 붙인다).
- **카피·숫자·고객명·로고에는 기본값이 없다.** 입력(사용자 메시지, 받은 문서, 캡처한 사이트 텍스트)에 없으면 묻는다. 그래도 없으면 화면에 쓰지 않거나 `[확인 필요]`로 남긴다.
- 확정 전에 요약을 한 번 보여 준다. 사용자가 말한 값과 기본·추론 값을 나눠 적고, 칸들이 합쳐져 생기는 충돌(예: 9:16인데 화면 문구가 길다, 15초인데 사실이 여덟 개다)이 있으면 조정안을 붙인다.

## 칸

| 칸 | 묻는 것 | 기본값 | 메모 |
|---|---|---|---|
| 메시지 | 영상이 남겨야 할 한 문장 | 없음 | 이 문장이 정해지기 전에는 스토리보드를 쓰지 않는다 |
| 하는 일과 가치 | 대상이 해 주는 일 3–5가지. 각각 **불편(전) → 하는 일 → 사용자가 얻는 것(후)** 세 칸과 근거(화면·문구·문서) | 없음. 원천에서 찾아 제안한다 | 소개 영상의 몸통이다. 메시지 한 문장만 받으면 "어디에 나오나"를 나열하게 된다. 하는 일만 받으면 기능 나열이 된다. 가치 문구도 원천에 있는 말만 쓴다. 원천에 가치 문장이 없는 일은 칸을 비워 두고 사용자에게 묻는다. 시간 절약·정확도 같은 숫자는 실제 데이터가 아니면 쓰지 않는다 |
| 깊이 | 티저(존재를 알림) / 소개(하는 일을 보여 줌) / 데모(흐름을 끝까지 시연) | 소개 | 티저가 아니면 장면마다 하는 일 하나를 보여 준다 |
| 시청자·채널 | 누가 어디서 보나(홈페이지 히어로, 링크드인, 유튜브, 쇼츠, 행사 화면) | 요청에서 추론 | 채널이 화면 비를 정한다 |
| 형식 | 그래픽형(내레이션 없음) / 내레이션형 | 길이·채널로 제안 | SKILL.md 라우팅 표로 워크플로가 갈린다 |
| 길이 | 초 | 그래픽형 15–30초, 내레이션형 30–60초 | 광고 컷 6–15초, 소셜·제품 데모 15–60초, 런칭 영상 30–90초 범위가 근거다. 첫 주 바이럴 업로드는 15초와 40초였다 |
| 화면·fps | 16:9 `1920x1080` / 9:16 `1080x1920` / 1:1 `1080x1080`, fps | 채널에서 유도, fps 30 | 60fps는 커서·스크롤·빠른 UI 모프가 있을 때만 |
| 카피 원천 | 화면 문구·내레이션의 출처 | 없음 | 사용자 원고, 사이트 캡처, 회사 소개서 등. 원고가 있으면 그대로 읽을지(verbatim) 재구성할지 묻는다 |
| 사실 원천 | 화면에 나올 숫자·고객사·인증·수상의 근거 | 없음 | 출처가 없는 사실은 화면에 올리지 않는다 |
| 브랜드 토큰 | `bg`, `fg`, `accent` 하나, 디스플레이 서체, 본문 서체 | 사이트 캡처 토큰 | 원천 우선순위: DESIGN.md → Figma(HyperFrames `/figma`) → 사이트 캡처 → hex 직접 입력. 브랜드 서체에 한글이 없으면 한글 짝 서체를 정한다 |
| 로고 | SVG 파일 경로 | 없음 | 없으면 "텍스트 마크로 간다"를 브리프에 명시해야만 텍스트 로고를 쓴다 |
| 화면 자료 | 제품 스크린샷, UI 녹화, 사진과 그 사용 권리 | 사이트 캡처 | 권리가 불분명한 제3자 화면은 쓰지 않는다 |
| 소리 | 음악(파일 경로 / 없음), 효과음(켬/끔), 내레이션 음성(성별·톤·속도) | 그래픽형은 효과음만 또는 무음 | 내레이션은 `openrouter.md`의 OpenRouter 경로 |
| 자막 | 내레이션형에서 자막을 넣을지 | 넣음 | 무음 자동재생 채널(링크드인, X 피드)은 자막이 사실상 필수 |
| 레퍼런스 | 참고 영상·이미지 1–2개 | 없음 | "리듬·질감·색만 가져온다"로 범위를 정한다. 없으면 금지 목록이 그 역할을 한다 |
| 금지 | 브랜드가 피해야 할 표현·색·톤 | `motion-rules.md` 기본 금지 목록 | 첫 결과를 본 뒤 늘린다 |
| 반복 재생 | 자동재생 루프로 쓰나(홈페이지 히어로 등) | 히어로면 루프 | 루프면 끝 프레임을 첫 프레임에 맞춘다 |
| 검토 방식 | 스토리보드를 승인받을지, 레이아웃 스케치까지 볼지 | 스토리보드 승인 + 스케치 생략 | `storyboard: yes`면 워크플로가 "스케치 먼저 볼지"를 묻는다. 여기서 정해 `## Notes`에 적어 두면 다시 묻지 않는다 |
| 승인자 | 스토리보드와 MP4 렌더를 누가 승인하나 | 요청자 | 렌더 게이트의 질문 대상 |

채널에서 화면 비를 정하는 기준(HyperFrames 브리프 계약과 같다):

| 채널 | 화면 |
|---|---|
| 유튜브, 웹사이트, 발표 화면 | `1920x1080` |
| 링크드인·X·인스타그램 피드 | `1080x1080` |
| 쇼츠·릴스·틱톡 | `1080x1920` |

사이트를 미리 캡처할 때는 `--json` 출력을 파일로 남긴다(`… --json > videos/.precapture-<project>/capture.json`). 워크플로 Step 1의 게이트가 `ok: true`를 확인한다.

## BRIEF.md로 남기기

`npx hyperframes init` 직후 프로젝트 루트에 `BRIEF.md`를 쓴다(`init`은 빈 폴더가 아니면 실패하므로 그 전에는 쓰지 않는다). HyperFrames 워크플로는 이 파일을 보면 인터뷰를 건너뛴다.

```markdown
---
workflow: product-launch-video        # 라우팅 표에서 고른 워크플로
flow: automation
storyboard: yes                       # 스토리보드 승인 게이트를 둔다
message: "<사용자가 확정한 한 문장>"
destination: website
aspect: 1920x1080
language: ko
audience: "<시청자>"
length: 30s
angle: "<워크플로 route 파일의 angle 중 하나와 고른 이유>"
narration: yes
---

## Intent

영상이 무엇이고 누구를 위한 것인지, 톤은 사용자의 말 그대로.

## Assets

- assets/brand/logo.svg — 공식 로고, 마지막 장면 락업
- assets/fonts/Pretendard-Bold.woff2 — 한글 디스플레이 서체

## Customizations

- 내레이션: OpenRouter `<모델 id>`, 음성 `<voice>`, 지시 "차분하고 확신 있는 30대 여성 내레이터"
- 자막: 켬(9:16 하단 안전 영역 밖)

## Notes

- 사실 원천: <사이트> 캡처(<날짜>), <문서> p.<쪽>
- [확인 필요] <원천이 없는 사실> — 화면에 쓰지 않음
- 금지: 그라데이션 위 가운데 제목, 파티클, UI 글로우
```

위 값은 형식 예시다. 실제 메시지·숫자·고객은 사용자 입력에서만 채운다.

그래픽형(내레이션 없음)은 이렇게 다르다.

- frontmatter에 `narration: no`를 쓴다.
- `## Customizations`에서 내레이션·자막 줄을 뺀다.
- 소리가 없으면 `## Notes`에 "완전 무음"이라고 적는다. 그러면 워크플로가 스토리보드 frontmatter에 `music: none`을 두고 `SCRIPT.md`를 만들지 않는다. 효과음만 쓰면 "효과음만"이라고 적는다.
- 루프 영상이면 `## Notes`에 "루프: 끝 프레임 = 첫 프레임"을 적는다.

fps는 BRIEF.md 키가 아니다. `## Notes`에 적고, 렌더할 때 `--fps`로 넘기거나 컴포지션의 `data-fps`에 둔다.

`aspect`는 `1920x1080`처럼 적고, `language`는 `ko`처럼 ISO 코드로 적는다. 선호 필드(`destination`, `aspect`, `language`, `voice`, `style_preset` 등)를 기억시키는 일은 HyperFrames 워크플로의 Setup이 한다. 사용자가 확인한 값만 기록된다.
