# 프로덕트 컨텍스트 레지스트리

매뉴얼 문구를 쓰거나 고치기 전에, 그 제품의 원천 문서를 로드해 용어·정책·객체
모델을 정확히 맞춘다 — 리포의 AGENTS.md 하네스가 강제하는 것과 같은 규율이다.
용어를 지어내거나 정책과 어긋나는 매뉴얼은 없느니만 못하다.

## 사용법

1. 어떤 제품의 매뉴얼인지 확인한다(불확실하면 물어본다).
2. 아래에서 해당 행을 찾아 **초안 전에 컨텍스트 폴더를 읽는다.** git URL이면 먼저
   최신으로 clone/pull한다(오래된 문서로 작업 금지 — 인증·네트워크·충돌로 pull이
   실패하면 추정하지 말고 멈추고 blocker를 보고한다).
3. 그 제품의 용어·톤 규칙을 적용한다. 확신 없는 영역(환자·녹음·기록 흐름, EMR,
   과금 등)을 다룰 땐 다시 읽는다.
4. 목록에 없는 **새 제품이면 먼저 사용자에게 확인한다** — 제품/폴더 이름과 컨텍스트
   폴더(정책 git 문서 폴더/리포)를 물어본다. 임의로 만들지 말고 확인부터. 확인받은
   뒤에:
   - (a) 산출물 폴더 `~/manuals/<제품>/`를 만든다(제품별 폴더로 관리).
   - (b) **아래 레지스트리에 새 행을 추가한다** — 그래야 다음 작업부터 이 스킬이
     그 제품을 자동으로 인식하고 컨텍스트·톤을 적용한다.

## 레지스트리

### 새록 (Saylog) — carevoice
- **컨텍스트 폴더(매번 읽기):** `https://github.com/douinc/carevoice/tree/main/docs/shared`
  — 폴더 전체를 읽는다(README, GLOSSARY, STATUS, 그리고 policies/guides/features/
  discussions/issues 하위 폴더). 특정 파일명에 의존하지 말고, pull 후 최신 내용을
  훑는다.
  - carevoice 리포를 로컬에 clone해 뒀다면 그 `docs/shared`를 읽어도 된다(경로는
    각자 환경마다 다름; 읽기 전에 `git pull`로 최신화). 없으면 위 git URL에서 받는다.
- **제품:** 모바일 앱 · 웹 콘솔 · **새록 라이브**(Windows/macOS 데스크탑 전사 앱)는
  각각 별도 파트이며 하나의 PDF로 함께 배포한다. 콘솔 URL: `console.carevoice.io`.
  - 새록 라이브 설계 SSOT: `carevoice/docs/superpowers/specs/2026-07-20-saylog-live-desktop-design.md`
    (라이선스 키 활성화 · 오버레이/클립보드 · 요약 서식 · 업데이트 · 에러 분기).
    디자인 시안 레포는 `saylog-live-design`(DS 개선 화면). 라이브 파트 소스는
    `manual-live.html`.
- **객체 모델(정책 기준):** 원본 녹음, 기록, 환자는 서로 구분되는 객체다 — 절대
  뭉뚱그리지 않는다. "환자 미지정/미연결"은 실제 환자도 가상 환자도 아니다; 정책대로
  모델링한다.
- **톤:** 의료진 대상 → 해요체 금지. 명사형·짧고 직관적("기록 시작", "환자 미연결").
  사용자에게 요청하는 문장만 `~해주세요`("다시 시도해주세요") 허용. 그 외에는
  `~합니다` / `~됩니다`; 리드문은 `~할 수 있습니다`.
- **플랫폼별 동사:** 모바일 앱 = "탭합니다"; 웹 콘솔 · 새록 라이브 = "클릭합니다".
  터치 기기는 탭, 데스크탑은 클릭 — 파트를 구분하는 표시이기도 하니 일관되게 유지한다.
- **디자인 기본값:** 브랜드 블루 번호 알약, Pretendard, 새록 로고, 표지 푸터에 "dou"
  회사 레터마크. 본문 13pt(독자 연령대가 높은 편).
- **소스·산출물:** 비공개 리포 `github.com/douinc/saylog-manuals`. clone 후
  `bash build.sh`로 두 에디션 PDF를 재생성한다(소스 HTML·`img/`·`img-app/`·로고·
  `build.sh` 포함). 새 병원 데모판 재사용은 그 리포 README의 체크리스트 참고.
  개인 작업 폴더는 `~/manuals/<제품>/` 규칙(각자 로컬).
